## 方案：vscode+foam+astro

### 1. 总体架构

三层分离架构，严格区分编辑态、构建态、发布态。单仓库 `www.haisong.cc-code` 存放代码与内容。

| 层级   | 职责                                         | 核心组件                                 | 状态/设置分离                                                                                                           |
| ------ | -------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 编辑层 | Markdown 创作、双向链接、图谱可视化、AI 辅助 | VSCode + Foam Extension Pack             | 设置：`.vscode/settings.json`、`.vscode/foam.json`；状态：`.foam/` 运行时索引、`_graph*.json`                           |
| 构建层 | 内容聚合、链接解析、静态生成、主题渲染       | Astro + Starlight + remark/rehype 插件链 | 设置：`astro.config.mjs`、`src/content/config.ts`；状态：`.astro/` 缓存、`dist/` 构建产物                               |
| 发布层 | 静态资源托管、反向代理、HTTPS、版本回溯      | Docker Compose + Traefik + Nginx         | 设置：docker-compose.yml、traefik.yml、nginx.conf、域名解析；状态：acme.json（证书）、dist/（构建产物）、容器运行时状态 |

### 2. 编辑层：VSCode + Foam

- 编辑器：VSCode
- 核心扩展：foam.foam-vscode（Wikilinks、反向链接、图谱导航）
- Markdown 增强：GFM、Mermaid、PlantUML
- 图片粘贴：mushan.vscode-paste-image，按「每篇笔记同名附件目录」规则落盘（见 3.5 图片附件规范）
  ```jsonc
  // .vscode/settings.json
  {
    "pasteImage.path": "${currentFileDir}/${currentFileNameWithoutExt}",
    "pasteImage.basePath": "${projectRoot}",
    "pasteImage.namePrefix": "",
    "pasteImage.showFilePathConfirmInputBox": false,
    "pasteImage.insertPattern": "![${imageName}](${currentFileNameWithoutExt}/${imageFileName})",
  }
  ```
- 笔记通过 frontmatter 控制发布闸门：`publish: true/false`

### 3. 构建层：Astro + Starlight

#### 3.1 选型依据

| 维度                 | Astro + Starlight          |
| -------------------- | -------------------------- |
| 零 JS 输出           | 支持（群岛架构）           |
| MDX 组件化           | 原生支持                   |
| Wikilinks `[[note]]` | 需 remark 插件             |
| Backlinks / 反向链接 | 需自研集成                 |
| 知识图谱可视化       | 前端自研组件               |
| 主题定制自由度       | 极高（Tailwind 可覆盖）    |
| 内容多源接入         | Content Collections 强类型 |

**结论**：Starlight 作为 Astro 的文档主题，提供文档站基础布局（侧栏/搜索/导航/i18n），同时保留群岛架构的完全自由度，适合叠加 Wikilinks / Backlinks / Graph 等知识库特性。

#### 3.2 核心依赖

```bash
npm create astro@latest . -- --template starlight --no-install

# 核心依赖
npm install astro @astrojs/starlight @astrojs/sitemap @astrojs/rss
npm install -D tailwindcss @tailwindcss/vite @astrojs/tailwind

# 图片处理（Content Collections 原生相对路径，构建期复制 + 哈希 URL）
npm install sharp

# remark 插件链（解析 Foam 语义）
npm install -D remark-wiki-link remark-gfm remark-breaks remark-frontmatter
npm install -D rehype-slug rehype-autolink-headings rehype-pretty-code
npm install -D @astrojs/mdx
```

#### 3.3 内容结构规划

**原则**：内容通过 Astro Content Collections 组织，按 Blog / Wiki（多领域）/ Solutions 三大类分区，每类内部按语义子路由细分，预留可扩展位。

**分类总览**：

| 大类               | 子分类 / 领域示例                                             | 说明                                                                    | 扩展策略                                                                                    |
| ------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **Blog**           | 长文（articles）、每日笔记（daily）                           | 对外公开发布的内容流                                                    | 新增 `blog-*` 前缀的内容源，如 `blog-podcast`、`blog-newsletter`                            |
| **Wiki（多领域）** | AI Coding、AI Agent 开发、软件工程、工具文档、技巧卡片        | 按领域拆分的知识库，每领域独立 Content Collection，内部继续按子主题分层 | 新增领域 collection（路由前缀 `/wiki/<领域slug>/`），或在 `/wiki/` 根下按子路由扩展细分领域 |
| **Solutions**      | 方案合集（solutions）、专题汇总（topics）、技术预研（spikes） | 跨领域的完整解决方案、专题聚合与验证性预研                              | 新增 `solution-*` 前缀的行业/场景方案，如 `solution-fintech`、`solution-aiops`              |
| **扩展位**         | —                                                             | 预留未来新大类（如 Offering、Projects、Cases 等）                       | 新增顶层路由前缀，配独立 Content Collection                                                 |

#### 3.4 关键能力

- **Wikilinks 解析**：remark-wiki-link 插件解析 `[[note]]` 与 `[[note|alias]]`，按 collection 与路由规则映射至对应 URL
- **Backlinks（反向链接）**：构建期遍历所有笔记生成反向链接索引，文章页底部渲染
- **知识图谱**：基于链接关系构建节点-边数据，D3.js 实现可交互图谱
- **全文搜索**：Pagefind 静态端搜索（支持中文分词）

#### 3.5 图片附件（方式 A：Content Collections 原生 + 同名附件目录）

**定位**：图片与 Markdown 共置，每篇笔记一个同名附件目录，Markdown 使用相对路径引用；Astro Content Collections 原生处理，无需手动映射。

**1. 目录布局（与 Markdown 共置）**

```
2-wiki/
├── solution-blog-wiki-tool.md                # 笔记
└── solution-blog-wiki-tool/                  # 同名附件目录
    ├── architecture.svg
    ├── dir-structure.png
    └── comparison-table.drawio.svg

1-articles/
├── 2026-ai-coding-review.md
└── 2026-ai-coding-review/                    # 图片/图表与笔记成对
    ├── benchmark.png
    └── workflow.mmd.svg
```

**2. Markdown 引用规范（标准相对路径）**：

粘贴图片一律使用相对路径，保证 VSCode 预览 / Foam 预览 / Astro 构建三者一致：

```markdown
![架构图](./solution-blog-wiki-tool/architecture.png)
```

> 注：粘贴动作由 2. 编辑层配置的 mushank.vscode-paste-image 设置自动生成符合规范的相对路径 Markdown 文本，无需手动编辑。

**3. Astro 图片处理配置（astro.config.mjs）**

```ts
// astro.config.mjs
import { defineConfig } from "astro/config";

export default defineConfig({
  // 使用 sharp 作为图片服务，构建期自动处理相对路径图片
  image: {
    service: { entrypoint: "astro/assets/services/sharp" },
  },
  // ...其余 integrations / markdown 配置不变
});
```

**构建行为**：

- Markdown 中所有 `![]()` 相对路径引用的图片，Astro 自动复制到 `dist/_astro/` 并改写为哈希 URL（缓存友好）；无需 public/ 软链或额外映射。

**4. 跨目录引用注意事项**

- 若出现跨目录引用其他笔记图片：优先在 Markdown 中写 `../另一个笔记目录/image.png` 依然能被正确解析
- Obsidian 风格嵌入图片 `![[xxx.png]]`（Wikilinks 图片嵌入）方式 A 默认不支持，使用标准 `![](./xxx/xxx.png)` 语法；如需兼容 `![[]]` 嵌入，可在后续扩展 `remark-wiki-link` 配置图片分支或用 `remark-obsidian-wikilinks` 插件。

### 4. 发布层：Docker Compose + Traefik + Nginx

#### 4.1 架构说明

- **Traefik**：反向代理入口，负责路由规则、TLS 终止、ACME 证书管理（acme.sh 手动签发后挂载）
- **Nginx**：静态资源托管，负责 gzip 压缩、缓存头、SPA fallback
- **Docker Compose**：服务编排与生命周期管理

#### 4.2 状态/设置分离

| 类别     | 内容                                                                   | 版本控制 |
| -------- | ---------------------------------------------------------------------- | -------- |
| **设置** | docker-compose.yml、traefik.yml、nginx.conf、服务标签路由规则          | 纳入     |
| **状态** | acme.json（证书）、dist/（构建产物）、容器运行时状态、Traefik 动态配置 | 不纳入   |

#### 4.3 核心编排

```yaml
# deploy/docker-compose.yml
services:
  traefik:
    image: traefik:v3.2
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./traefik.yml:/etc/traefik/traefik.yml:ro
      - ./acme:/acme

  wiki:
    image: nginx:1.27-alpine
    restart: unless-stopped
    volumes:
      - ../dist:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.wiki.rule=Host(`wiki.yourdomain.com`)"
      - "traefik.http.routers.wiki.tls.certresolver=acme"
```

> 证书管理按用户偏好：网络不稳定时使用 acme.sh 半自动签发后挂载到 traefik，避免 ACME 自动重试失败。
